## Decisiones
6.1 cliente HTTP tipado consulta inventario SQL por red. Diferenciar404 de error servidor, disponer respuesta, propagar cancelación. Consulta informativa, no reserva ni transacción distribuida.
6.2 planificar OrdenProduccion existente + MensajeSalida en un SaveChanges; concurrencia optimista y unicidad OrdenId. Publicador confirma broker antes de marcar enviado. Consumidor confirma mensaje después de persistir recibo/proyección SQL; misma id/payload no duplica, id reutilizada con otro payload se rechaza. Cola durable, mensajes persistentes, DLQ para mensajes incompatibles; requeue ante fallo técnico. Workers opcionales por configuración, activos en recorrido real. BasicGet se usa como polling didáctico, no se presenta como diseño de alto rendimiento.
6.3 consulta informativa de cada material antes de planificar,202 con lectura posterior eventual. No se promete reserva de stock ni exactamente una vez. Controlador devuelve404 orden ausente,409 transición o disponibilidad,503 fallo remoto.
